`xs serve` can now load Nushell plugins, thanks to @kiil (#176).

Until now the engine embedded in xs had no way to load plugins, so an actor that used `query web` failed to register with a parse error, and one that used `polars` failed on its first frame with `Command polars not found`. Pass each plugin binary with `--plugin`:

```sh
xs serve ./store --plugin /path/to/nu_plugin_query --plugin /path/to/nu_plugin_polars
```

Their commands are then available to `xs eval`, and to actors, services and actions:

```nushell
{
  run: {|frame, state = null|
    {out: {headings: (.cas $frame.hash | query web --query "h1" | flatten)}, next: $state}
  }
  topics: ["page.html"]
}
```

xs starts each plugin once at startup to read its commands, and every engine shares that one process. If a path is wrong or a plugin won't load, `xs serve` stops straight away with an error naming the path. Without `--plugin`, nothing changes.
