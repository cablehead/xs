## Breaking changes

- **A following read now ends when it falls behind** (#160). xs holds 4096 live frames for a reader. A reader that got further behind than that used to lose the frames in between, and got a log line it could not see. It saw a stream with a hole in it and no way to know. The read now ends instead. To carry on, read again with `after` set to the last id you received.

- **Frames with a `ttl: time:<ms>`, written before this release, stay on disk forever.** They still vanish from reads when they expire. But the new sweeper, below, works from an index that only newer frames have, so nothing deletes them. Export the store and import it again to get the space back.

- **`.id unpack` returns a different shape** (#149). `ts_ms` replaces `timestamp`. It is an integer in milliseconds, and `pack` reads it back exactly. A new `when` field shows the same time as a datetime, which `pack` ignores. Update scripts that read `timestamp`.

- **`xs::nu::ReadMode` is gone, and `Store::read` is now synchronous** (#146). If you embed xs, remove the `.await` and the mode argument.

- **xs needs Rust 1.96.1** and uses Nushell 0.116.0 (#159). Nushell deprecated `get -i` and `reject -i`. Use `-o` instead (#162). [@kiil](https://github.com/kiil) raised both, in #153 and #152.

## Highlights

- **xs now deletes expired frames from disk.** A frame with a `ttl: time:<ms>` expires that many milliseconds after it is written. Before, a read hid an expired frame and queued it for deletion, so a frame that nobody read was never deleted. A sweeper now runs every second and deletes up to 4096 frames each pass. Set the interval with `xs serve --ttl-sweep`.

- **Retention costs a fraction of what it did.** Enforcing `ttl: last:<n>` used to scan a topic once for every append waiting in the queue, and start each scan from the beginning. It now scans once per batch, resumes where the last scan stopped, and deletes a frame from what the index already told it. A burst of 20,000 appends to a topic under `ttl: last:1000` took 4,190 ms. It now takes 11 ms.

- **`xs cat` is 20 times faster** (#155, [@kiil](https://github.com/kiil)). It wrote and flushed each frame on its own. It now fills a buffer of up to 256 KiB and writes once. A 500k frame store took 7.3 s. It now takes 0.35 s, which is what `curl` costs against the same socket. `--follow` still sends each frame as it arrives.

- **Appends without a body are 3 times faster** (#157, [@kiil](https://github.com/kiil)). Every append opened a CAS writer before it knew whether a body followed, and opening one creates a temp file. It now opens the writer on the first chunk of the body. One connection did 9,900 appends a second. It now does 34,600.

- **`GET /metrics` reports counters.** You get fjall's cache and filter counters for each keyspace, plus the store's own: how many appends it took, how many frames a read scanned against how many it returned, and what retention cost. Every counter is cumulative, so read it twice and subtract to get a rate.

- **`xs serve --fsync` sets the fsync policy.** It defaults to `interval:1000`.

- **A service can restart when its pipeline finishes cleanly.** `restart: "on-success"` is the default. Use `"never"` to stop after one run.

## Bug fixes

- `read_sync` collected every frame before it returned the first one. On a 10M frame store that held about 1.7 GB, and it peaked near 3.4 GB while the vector grew. It now streams.
- fjall ran with one worker thread. One thread starves its flushes under a steady write load, so writes stopped reaching disk. It now runs with two.
- Re-importing a frame under a new topic left the old index entry in place, so the frame answered to both topics. Changing its ttl left the old expiry entry behind (#161).
- A scru128 id lost precision in `pack`, so `unpack | pack` did not return the same id (#147).
- Each `.cat` and `.last` leaked a tokio runtime (#146).
- A topic read with a `from` or `after` bound scanned the topic from the start. It now seeks to the bound.
- `xs.stopping` now runs on SIGTERM and on a Windows console close. Before, it ran only on ctrl-c.
- A new engine no longer inherits `XS_APPEND_META`. Only xs sets that variable.
- The Discord example stopped its reconnect loop after a failed identify.
