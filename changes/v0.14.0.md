## Highlights

- **Nushell 0.115.1.** The embedded engine moves from 0.113.1 to 0.115.1 and the minimum Rust version to 1.95.0. The standalone `nu` used in CI and the Docker image moves with it.

- **Expired `time:` frames are swept in the background.** Each `time:` frame now gets an entry in an expiry index, and a gc sweep removes due frames every `--ttl-sweep` milliseconds (default 1000, 0 disables it), up to 4096 per batch. Reads still hide an expired frame but no longer queue its removal. Frames written by earlier versions are not swept; see Upgrading.

- **Configurable fsync.** `xs serve --fsync` takes `always`, `interval:<ms>`, or `never`. The default is `interval:1000`. Every append still commits to the journal before it returns, so a process crash loses nothing; the policy decides how much a power loss can take. Embedders use `Store::with_fsync` and `Store::flush`.

- **Services can stop after one run.** A new `restart` option: `on-success`, the default, keeps the existing auto-restart when a pipeline drains cleanly. `never` makes a clean finish terminal and emits `xs.service.<name>.fin.ok`. A pipeline that errors is not restarted under either policy.

- **`.cat` / `.last` no longer leak file descriptors.** Each call used to build its own tokio runtime, and a `--follow` read whose consumer went away kept it alive for the life of the process, until the process hit the open-file limit. Reads now share the store's runtime and stop when the receiver drops. Historical reads stream lazily instead of collecting the backlog first. (#146)

- **Large topics are cheaper to read and to clean up.** Topic reads seek to the `from` / `after` bound instead of scanning from the topic's first entry. Topic scans skip expired frames without a point read. The expiry sweep and the `last:n` trim resume where they stopped instead of rewalking their own tombstones. A `last:n` topic is scanned once per gc drain, not once per append: 20,000 appends to a `last:1000` topic took the drain from 4.19s to 11ms.

- **`GET /metrics`** returns cumulative store and fjall keyspace counters as JSON.

- **Fixes:**
  - fjall ran with one worker thread, which could stall memtable rotation under a steady append load. It now runs with two.
  - `.cat --follow` no longer ends silently when a reader falls more than 1024 frames behind. It logs the skipped count and keeps following.
  - `xs.stopping` runs on SIGTERM and on Windows console-close, not just ctrl-c. (#150)
  - `.id unpack | .id pack` roundtrips losslessly. It used to drop a millisecond on about 3% of ids. (#149)
  - iroh 1.1.0, plus a connection-lifetime bug it exposed.
  - An `XS_APPEND_META` inherited from the environment no longer leaks into a new engine.

## Upgrading

This release has breaking changes.

- **Old `time:` frames are never swept.** Frames written before 0.14.0 have no expiry entry. Reads hide them once expired, but they stay on disk. There is no backfill.

- **`.id unpack` output changed.** The float `timestamp` field is replaced by `ts_ms`, the integer milliseconds and the authoritative value, and `when`, a datetime for display. Scripts that read `.timestamp` should read `ts_ms` or `when`. (#149)

- **Embedders (Rust API):**
  - `xs::nu::ReadMode` is gone. `add_read_commands(engine, store)` takes two arguments, and one `.cat` / `.last` pair serves every caller.
  - `Store::read` is sync and returns a `tokio::sync::mpsc::Receiver<Frame>` directly. Drop the `.await`.
  - `.cat` / `.last` read with `blocking_recv` on the store's runtime, so an engine that runs them must not be evaluated inside an async context. `spawn_blocking` or a plain `std::thread` is fine.
  - The `nu-*` crates are 0.115.1. An embedder that shares Nushell types with xs needs the same versions.
  - On Windows, `win_uds` is pinned to `=0.2.4`. A crate that pins it exactly must match.
