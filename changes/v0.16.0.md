| per append, a topic held at `n` by `last:n` | 0.15.1 | 0.16.0 |
|---|---|---|
| index entries read, `n` = 50,000 | 50,001 | 1 |
| gc work, `n` = 50,000 | 17.66 ms | 0.14 us |
| index entries read, `n` = 5,000,000 | 5,000,001 | 1 |
| gc work, `n` = 5,000,000 | 759.3 ms | 0.13 us |

## `last:n` from a per-topic count (#181)

The store keeps a frame count for each `last:n` topic. An append that takes a topic over `n` removes the oldest frame in the same commit; 0.15.1 scanned back `n` index entries on every such append. A topic is counted the first time a `last:n` frame lands on it, so a 0.15 store opens as is. Appends without `last:n` are within about 2% of 0.15.1.

A topic is trimmed by an append that carries `last:n`. Appends without it can take the topic past `n`; the next `last:n` append brings it back.

## `POST /append-batch` (#158)

By [kiil](https://github.com/kiil).

```sh
printf '%s\n' \
    '{"topic":"clip.add","meta":{"n":1}}' \
    '{"topic":"clip.add","meta":{"n":2},"ttl":"last:100"}' |
  curl --unix-socket ./store/sock --data-binary @- http://localhost/append-batch
```

Each NDJSON line is a frame: `topic`, and optionally `meta`, `ttl` and `hash` (content stored with `POST /cas`). The frames get consecutive ids and commit together. A malformed line, an invalid topic, or more than 1024 frames returns 400 and stores nothing.

| one connection | frames/s |
|---|---|
| `POST /append/{topic}`, 1 frame per request | 29,700 |
| `POST /append-batch`, 1000 frames per request | 397,000 |

## Unused content is deleted (#184)

| content | 0.15.1 | 0.16.0 |
|---|---|---|
| of a removed or trimmed frame | kept | deleted after an hour |
| of an ephemeral frame | kept | deleted after an hour |
| from `POST /cas`, no frame points at it | kept | deleted after an hour |

Deletion runs when the server starts, and on `POST /gc`:

```sh
$ curl --unix-socket ./store/sock -X POST http://localhost/gc
{"in_use":18,"recent":87,"deleted":28720,"bytes_freed":10700000000}
```

## Breaking

- Nushell 0.117.0 and Datastar 1.0.5 (#178). Code that embeds xs needs `nu-*` 0.117.
- Content no stored frame points at is deleted after an hour (#184). To keep content, point a frame at it.
- Don't open a store with 0.15 after 0.16 has used it (#181). 0.15 doesn't update the counts, and a count left too high makes 0.16 trim frames it should keep.
